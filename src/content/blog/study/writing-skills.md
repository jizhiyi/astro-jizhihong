# 技术写作指南

我写技术博客已经两年了，从最初的流水账到现在的有体系，踩过不少坑。这篇文章分享我的技术写作方法和心得。

## 为什么要写作

### 对个人

1. **知识巩固** —— 写出来才是真的懂
2. **思维整理** —— 写作是很好的思考方式
3. **个人品牌** —— 建立影响力
4. **面试加分** —— 有博客是加分项

### 对他人

1. **帮助新人** —— 少走弯路
2. **记录经验** —— 方便以后回顾
3. **社区贡献** —— 技术圈需要分享

## 写作准备

### 选题

好的选题是成功的一半：

**好选题的特征**
- 解决实际问题
- 目标读者明确
- 有独特角度
- 时效性不太强

**选题来源**
- 工作中的问题
- 学习中的困惑
- 社区的热门话题
- 自己的实践总结

**选题列表**

我有一个专门的文档记录选题：

```
# 选题列表

## 待写
- React Hooks 最佳实践
- TypeScript 进阶技巧
- 前端性能优化实战

## 规划中
- 微前端架构设计
- 团队代码规范

## 已完成
- Git 使用技巧
- VS Code 插件推荐
```

### 受众

写之前要想清楚：

1. **谁会看这篇文章**
   - 新手？进阶？专家？
   - 前端？后端？全栈？

2. **读者想知道什么**
   - 概念？实践？深入原理？
   - 入门？面试？工作流？

3. **读者的水平**
   - 需要多少前置知识
   - 要不要解释基础概念

### 结构

技术文章常用结构：

**总-分-总**
```
1. 引入：为什么写这个
2. 主体：分几个部分讲解
3. 总结：回顾要点
```

**步骤式**
```
1. 第一步
2. 第二步
3. 第三步
...
```

**问题-方案**
```
1. 问题是什么
2. 解决方案
3. 代码示例
4. 注意事项
```

## 写作技巧

### 标题

**好标题的特征**
- 清晰表达内容
- 吸引读者
- 包含关键词

**标题模板**
- 《XXX 实战指南》
- 《XXX 最佳实践》
- 《一文读懂 XXX》
- 《XXX 原理深度解析》
- 《如何XXX（步骤指南）》

### 开头

开头要抓住读者：

```markdown
# 引入方式

## 问题引入
在开发中，我们经常会遇到 XXX 问题...

## 数据引入
根据调查，XXX 是最常见的问题...

## 场景引入
当你需要 XXX 时，是不是经常...
```

### 代码

技术文章离不开代码：

**代码块**
- 标注语言
- 重要行加注释
- 不要放完整代码（会很长）

**代码展示**
```javascript
// ✅ 好的代码示例
// 注释解释关键逻辑
function debounce(fn, delay) {
  let timer = null;
  return function (...args) {
    if (timer) clearTimeout(timer);
    timer = setTimeout(() => {
      fn.apply(this, args);
    }, delay);
  };
}
```

**代码解释**
- 先展示代码
- 再解释每部分
- 最后说为什么这样写

### 图表

适当使用图表：

**什么时候用**
- 流程图：展示流程
- 时序图：展示交互
- 对比图：展示区别
- 架构图：展示结构

**工具推荐**
- Mermaid（代码画图）
- Excalidraw（手绘风格）
- draw.io

### 总结

结尾要到位：

```markdown
## 总结

本文介绍了 XXX，主要包括：

1. 概念
2. 原理
3. 实践

通过本文，你应该：

- 理解 XXX
- 掌握 XXX
- 能够 XXX

如果有问题，欢迎评论区交流。

## 参考

- [链接1]
- [链接2]
```

## 写作流程

### 1. 收集素材

- 工作中遇到的问题
- 学习时做的笔记
- 代码片段
- 参考文献

### 2. 列出大纲

```
# 文章大纲

## 引言
- 背景
- 目标

## 主体1
- 要点1
- 要点2

## 主体2
- 要点1
- 要点2

## 总结
- 回顾
- 展望
```

### 3. 填充内容

按大纲写，不要追求完美：
- 先写出来
- 再修改
- 最后润色

### 4. 检查修改

**语法检查**
- 错别字
- 标点符号
- 语法错误

**逻辑检查**
- 论证是否充分
- 例子是否恰当
- 是否有漏洞

**代码检查**
- 语法正确
- 可以运行
- 注释清晰

### 5. 排版美化

- 段落不要过长
- 适当使用列表
- 加粗关键点
- 保持格式一致

## 常见问题

### Q: 写不出来怎么办？

A:
1. 从小话题开始
2. 先列大纲
3. 想到什么写什么
4. 不要追求完美

### Q: 内容太浅怎么办？

A:
- 可以深入原理
- 可以讲实践
- 可以对比分析
- 可以总结经验

### Q: 不知道写什么？

A:
- 记录工作中遇到的问题
- 总结学习心得
- 分享项目经验
- 翻译外文文章

### Q: 写太长没人看？

A:
- 控制篇幅（2000-4000 字）
- 分章节
- 加目录导航
- 结论先行

### Q: 没人点赞？

A:
1. 持续写，坚持积累
2. 选好平台
3. 适当推广
4. 质量是关键

## 我的写作习惯

### 写作频率
- 每周 1-2 篇
- 长文月度 1 篇
- 短文每周 2-3 篇

### 写作时间
- 早上：构思和写大纲
- 周末：集中写
- 碎片时间：收集素材

### 质量控制
- 写完读 3 遍
- 请同事 review
- 定期回顾修改

## 总结

技术写作的价值：
- 巩固知识
- 建立品牌
- 帮助他人
- 锻炼思维

写作技巧：
- 选题要好
- 结构要清
- 代码要对
- 解释要透

最重要的是：**开始写，持续写**。

刚开始写得不好很正常，坚持写下去自然会进步。
